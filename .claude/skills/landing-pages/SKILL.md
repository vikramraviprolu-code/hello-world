# Landing pages — product-site copy that converts humans

`geo` makes a page citable by AI engines; this skill makes the same page
convert the humans who land on it. Run both on any product page.

> **Provenance:** the frameworks here are distilled from widely-known
> conversion and copywriting principles associated with Julian Shapiro's
> Landing Pages and Writing Well handbooks (julian.com), restated in our own
> words — never verbatim. Treat as a solid working model; true it up against
> the source text when it's accessible (see CLAUDE.md — the site is blocked
> from cloud sessions). Frameworks aren't copyrightable; his exact wording is.

## Core principle

**Clarity beats cleverness, every time.** A confused visitor leaves. Before
any persuasion, a first-time visitor must answer three questions within ~5
seconds of the fold: *What is this? Is it for me? What do I do next?* If the
page fails that test, nothing below the fold matters.

## Workflow

### 1. Establish the essentials (ask or locate)

- The **one** primary audience (not "everyone").
- The single most compelling **end-benefit** (outcome, not feature).
- The primary **conversion action** (one CTA goal per page).
- Proof available: users, logos, metrics, testimonials, demos.

### 2. Audit or draft against the page anatomy

Use `reference/page-anatomy.md` — section-by-section structure (hero →
value prop → how it works → proof → objections → CTA) with what each must
accomplish. For an existing page, score each section PASS/WEAK/MISSING and
report before changing anything.

### 3. Rewrite the copy

Apply `reference/copy-principles.md`: benefit-led headlines, the specificity
rule, the "delete test" (would the reader miss this sentence?), and the
hook-chain (each sentence earns the next). This is the human mirror of geo's
anti-slop pass — run them together.

### 4. Report

Changes made, section coverage after, and the top 3 conversion risks still
open. Never invent testimonials, user counts, or metrics — if proof is
missing, flag it as a gap for the user to supply, don't fabricate it.

## Scope boundaries

- Visual/UX design, page speed, and A/B test infrastructure are out of
  scope — this skill is copy and page structure. Recommend a design/CRO
  pass for the rest.
- AI-citation optimization is the `geo` skill's job; invoke it in the same
  pass so the page serves both humans and answer engines.
- Never fabricate proof. Persuasion built on invented numbers is both a
  trust risk and, for real products, a legal one.
